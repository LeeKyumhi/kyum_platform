# 1인 창업자의 조직 설계 가이드
### 사람은 언제 뽑고, AI 직원은 어떻게 만드는가 (2026년 7월 기준)

> 앞서 만든 법률 가이드(근로계약·4대보험)와 재무 가이드(원천세·두루누리)의 조직 버전입니다. 노무 관련 결정은 노무사 확인을 권장합니다.

---

## 핵심 원칙 — "직원"이 아니라 "기능"을 채운다

스타트업에 필요한 것은 사람이 아니라 **기능**입니다: 개발, 디자인, 마케팅, CS, 회계, 법무, 데이터 분석. 각 기능은 네 가지 방법으로 채울 수 있고, 비용 순서는 대략 이렇습니다.

1. **창업자 본인** (시간이 비용)
2. **AI** — Claude, Claude Code 에이전트 (월 수만~수십만 원)
3. **외주·전문가** — 프리랜서, 세무사, 노무사 (건별·월별)
4. **정직원** (가장 비싸고 가장 되돌리기 어려움)

**정직원 1명의 진짜 비용 = 연봉 × 약 1.3~1.5배.** 4대보험 회사부담분 약 10~11%, 퇴직금 적립 약 8.3%, 장비·공간·관리 비용이 붙습니다. 연봉 3,600만원 직원은 실제로 월 400만원 이상의 고정비 = **런웨이를 직접 깎는 결정**입니다. 그래서 순서는 언제나: 본인+AI로 시작 → 반복되고 커지면 외주 → 핵심이고 상시적이면 그때 채용.

**결론부터: 검증~출시 단계의 필수 정직원 수는 0명입니다.** 아래는 그 0명을 가능하게 하는 설계입니다.

## 1. 인간을 쓰는 5가지 형태 — 언제, 무엇을

| 형태 | 언제 쓰나 | 비용·세무 처리 | 법적 의무 | 주의점 |
|---|---|---|---|---|
| **프리랜서** | 로고, 일러스트, 특정 기능 등 스팟 작업 | 대금의 3.3% 원천징수 후 지급, 다음 달 10일 신고 | 계약서(결과물·IP 귀속 명시) | 출퇴근·업무 지시하면 실질상 근로자로 판정될 위험(위장 프리랜서) |
| **외주 업체** | 디자인 시스템, 마케팅 대행 등 큰 덩어리 | 세금계산서 수취 | 용역계약서 | 저작권 귀속·하자보수·유지보수 조항 필수 |
| **초단시간 알바** (주 15시간 미만) | CS 응대, 콘텐츠 업로드 등 가벼운 반복 업무 | 시급제 | **근로계약서는 필수**, 최저임금 적용 | 주 15시간 미만이면 주휴수당·퇴직금 등 일부 의무 제외 — 첫 인력 실험으로 적합 |
| **계약직·단시간 근로자** | 검증된 업무를 기간 정해 맡길 때 | 4대보험 가입 | 근로계약서, 연차 등 | 2년 초과 사용 시 무기계약 근로자로 간주(기간제법) |
| **정규직** | 핵심이고 상시적인 기능 | 연봉 × 1.3~1.5 | 근로계약서, 4대보험, 퇴직금, 연차 | 채용 전 두루누리(4대보험 최대 80% 지원)·청년 채용 장려금 확인 |

**공동창업자는 고용이 아닙니다** — 지분 파트너입니다. 법률 가이드 6장의 동업계약서(지분, 베스팅, 퇴사 처리)로 다루세요.

## 2. 첫 채용의 타이밍과 대상

**채용 트리거 — 세 가지가 모두 참일 때만:**
1. 특정 업무가 **주 20시간 이상** 반복적으로 내 시간을 먹고 있다
2. AI와 외주로 시도했는데 **품질이나 속도가 안 나온다**
3. 그 사람이 만들 매출·절감이 **인건비(×1.4)보다 크다는 계산**이 선다

**기술 창업자의 1호 채용 우선순위** (개발은 본인이 하므로):
- **B2C 서비스**: 마케팅·그로스 담당 — 제품은 있는데 알리는 사람이 없는 게 병목
- **B2B 서비스**: 영업 또는 CS — 신뢰 관계는 사람이 만듦
- 개발 속도 자체가 병목이면 개발자 — 단, 가장 비싸고 관리 부담도 커서 마지막 선택지

채용 결재 전 마지막 질문: **"이 업무, Claude Code 에이전트나 자동화로 한 번 더 시도해봤나?"**

## 3. AI 조직도 — Claude Code 에이전트 "직원들"

### 3-1. 서브에이전트란 무엇인가

Claude Code의 **서브에이전트(subagent)** 는 각자 자기만의 시스템 프롬프트(역할 정의서), 독립된 컨텍스트 윈도우(작업 기억), 지정된 도구 권한을 가진 전문 AI입니다. 메인 Claude가 작업을 만나면 각 에이전트의 description을 보고 적합한 전문가에게 위임하고, 에이전트는 독립적으로 일한 뒤 요약만 돌려줍니다 — 회사로 치면 팀장이 실무자에게 업무를 배분하는 구조예요.

**만드는 방법 두 가지:**
- Claude Code 안에서 `/agents` 명령 → 대화형으로 생성 (처음엔 이걸 추천)
- 프로젝트의 `.claude/agents/` 폴더(이 프로젝트 전용) 또는 `~/.claude/agents/` 폴더(내 모든 프로젝트 공용)에 마크다운 파일을 직접 작성

**파일 구조 해부:**

```markdown
---
name: code-reviewer          # 에이전트 고유 이름 (호출할 때 사용)
description: 언제 이 에이전트를 쓸지 설명  # 메인 Claude가 이걸 보고 자동 위임 여부를 판단
tools: Read, Grep, Glob, Bash # 허용할 도구만 제한 (생략하면 전체 상속)
model: sonnet                 # 사용할 모델 (비용·성능 조절)
---
여기부터가 시스템 프롬프트.
이 에이전트의 역할, 일하는 순서, 출력 형식을 적습니다.
```

윗부분(`---` 사이)은 **YAML 프론트매터**라고 부르는 설정 영역이고, 아래 본문이 그 에이전트의 "업무 매뉴얼"입니다. description에 "코드 변경 후 반드시", "proactively(선제적으로)" 같은 표현을 넣으면 시키지 않아도 알아서 투입되는 빈도가 올라갑니다.

### 3-2. 추천 AI 직원 명단 (6명)

| 직함 | name | 하는 일 | 투입 시점 |
|---|---|---|---|
| 시니어 코드 리뷰어 | code-reviewer | 변경 코드의 버그·보안·가독성 리뷰 | 매 커밋 전 |
| 보안 담당자 | security-auditor | 키 노출, RLS 누락, 인증 구멍 점검 | 인증·결제 작업 시, 배포 전 |
| QA 엔지니어 | test-writer | 새 기능의 테스트 코드 작성·실행 | 기능 완성 직후 |
| 테크니컬 라이터 | docs-writer | README, API 문서, 변경 이력 갱신 | 주 1회 |
| 데이터 분석가 | metrics-analyst | DB에서 SQL로 지표 뽑아 주간 리포트 | 출시 후 매주 |
| CS 초안 담당 | cs-drafter | FAQ 기반 고객 문의 답변 초안 | 문의 올 때 |

전부 한 번에 만들지 마세요. 실무 사용자들의 공통 조언은 **3~4개에서 시작**하는 것입니다 — 에이전트가 많아지면 오히려 관리 비용이 생산성을 깎습니다. 개발 단계에서는 code-reviewer와 security-auditor 둘이면 충분합니다.

### 3-3. 실제 파일 예시 ① — 시니어 코드 리뷰어

`.claude/agents/code-reviewer.md` 로 저장:

```markdown
---
name: code-reviewer
description: 코드를 새로 작성하거나 수정한 직후 반드시 사용. 커밋 전에
  proactively 실행해 버그, 보안 문제, 가독성을 점검한다.
tools: Read, Grep, Glob, Bash
---

너는 10년차 시니어 개발자이자 이 스타트업의 코드 품질 최종 책임자다.
스택: Next.js + Supabase + Vercel. 개발자는 학습 중인 주니어이므로
지적할 때 반드시 "왜 문제인지"를 한 줄 설명한다.

호출되면 순서대로:
1. `git diff HEAD` 를 실행해 최근 변경사항만 파악한다
2. 아래 체크리스트로 점검한다
   - 명백한 버그, 처리되지 않은 에러(try/catch 누락, null 가능성)
   - 하드코딩된 비밀값(API 키, 비밀번호)
   - 중복 코드, 지나치게 긴 함수
   - 성능 함정(불필요한 리렌더, N+1 쿼리)
3. 결과를 세 등급으로 보고한다
   - [수정 필수] 배포 전 반드시 고칠 것
   - [권장] 지금 고치면 좋은 것
   - [제안] 나중에 개선할 것

솔직하고 비판적으로 평가하라. 칭찬으로 시작할 필요 없다.
문제가 없으면 "통과 — 특이사항 없음" 한 줄로 끝내라.
```

**코드 해설**: `tools`에 Read·Grep·Glob·Bash만 준 이유 — 리뷰어는 코드를 "읽고 검사"만 해야지 직접 고치면(Write/Edit) 안 되기 때문입니다. 권한을 좁히는 것 자체가 안전장치예요. 본문 마지막의 "칭찬으로 시작할 필요 없다"는 AI 특유의 무조건 동조를 끄는 장치이고, "통과 한 줄" 규칙은 보고 노이즈를 줄입니다.

### 3-4. 실제 파일 예시 ② — 보안 담당자

`.claude/agents/security-auditor.md` 로 저장:

```markdown
---
name: security-auditor
description: 인증, 결제, DB 접근, 환경변수를 다루는 코드를 작성·수정할 때,
  그리고 배포 전 점검 요청 시 사용한다.
tools: Read, Grep, Glob, Bash
---

너는 이 서비스의 보안 담당자다. Next.js + Supabase 스택 기준으로 점검한다.

점검 항목:
1. 비밀값 노출 — `grep -rn "sk-\|secret\|password\|api_key" --include="*.ts" --include="*.tsx" .`
   등으로 하드코딩된 키 탐색. .env 파일이 .gitignore에 있는지 확인
2. Supabase RLS — 모든 테이블에 행 수준 보안(Row Level Security) 정책이
   있는지, "자기 데이터만 접근" 규칙이 빠진 테이블이 있는지
3. service_role 키가 클라이언트 코드(브라우저에 배포되는 파일)에
   포함되지 않았는지 — 이 키는 서버 전용이다
4. 사용자 입력 검증 — 폼·쿼리 파라미터가 검증 없이 DB에 들어가는 경로
5. 인증 없이 접근 가능한 API 라우트 목록

보고 형식: 발견 사항마다 [치명 / 높음 / 중간] 위험도 + 파일 위치 +
구체적 수정 방법. 치명 항목이 하나라도 있으면 첫 줄에 "배포 중단 권고"라고 쓴다.
```

**코드 해설**: 2번 RLS 점검이 Supabase 초보의 최다 사고 지점입니다 — RLS를 안 켜면 모든 사용자가 모든 데이터를 읽을 수 있어요. 3번 service_role 키는 관리자 전권 키라서 브라우저에 노출되는 순간 DB 전체가 뚫립니다. 이 두 가지만 자동 점검돼도 초기 보안 사고의 대부분을 막습니다.

### 3-5. AI 직원 운영 수칙

- **CLAUDE.md가 진짜 핵심입니다.** 프로젝트 루트의 CLAUDE.md는 모든 에이전트가 읽는 "회사 온보딩 문서" — 기술 스택, 폴더 구조, 코딩 규칙, 자주 쓰는 명령어를 여기 적어두면 모든 AI 직원의 업무 품질이 함께 올라갑니다. 에이전트를 늘리기 전에 이 문서부터 다듬으세요.
- **최종 검토는 항상 사람.** 커밋 전 `git diff` 확인, 특히 DB 마이그레이션과 배포는 반드시 직접 승인. AI 직원의 실수도 법적 책임은 대표(당신)에게 있습니다.
- **반복 업무는 헤드리스 모드로.** `claude -p "지시문"` 형태로 스크립트에서 호출할 수 있어, 주간 지표 리포트 같은 정기 업무를 cron이나 GitHub Actions에 걸어 자동화하는 패턴이 실무에서 쓰입니다.
- 비용 감각: 에이전트 6명을 부려도 월 구독료는 신입 알바 하루 일당 수준입니다. 다만 토큰 사용량이 큰 작업은 요금제 한도를 확인하세요.

## 4. Claude(이 채팅)가 맡는 역할 — 경영지원실

Claude Code가 "개발팀"이라면, 이 채팅(claude.ai)은 **기획·경영지원실**입니다. 이번 대화에서 이미 한 일이 곧 직무기술서예요:

- **공동 기획자**: 창업 로드맵 설계, 단계별 전략 논의 (지금 하는 것)
- **리서치 담당**: 최신 법 개정·세제 확인처럼 검색이 필요한 조사
- **문서 담당**: 법률·재무 가이드, 이용약관·개인정보처리방침 초안, 사업계획서·IR 자료 초안
- **사내 도구 제작**: 체크리스트 앱 같은 소규모 도구
- **재무 담당 보조**: 현금흐름표, 가격 시뮬레이션 (엑셀 모델 제작 가능)
- **코드 과외 선생**: 개발 중 막힌 개념을 코드와 함께 설명
- **번역·현지화, 마케팅 카피 초안**

**도구 구분 요령**: 코드베이스를 직접 만지는 일 → Claude Code. 생각·조사·문서·결정 → claude.ai 채팅. 문서·엑셀 중심의 사무 업무를 에이전트에게 통째로 맡기고 싶어지면 Claude Cowork(비개발자용 에이전트 앱)도 있습니다.

## 5. AI가 대체할 수 없는 것 — 창업자 고유 업무

이건 아무리 바빠도 위임하면 안 되는 목록입니다.

1. **고객 인터뷰와 관계** — Phase 1의 핵심. 고객의 표정, 머뭇거림, 진짜 불만은 창업자가 직접 들어야 제품이 됩니다. AI는 질문지 설계와 녹취 분석까지만.
2. **최종 의사결정과 법적 책임** — 2026년 개정법이 대표자를 개인정보 보호의 최종 책임자로 명문화했듯, 모든 결과의 책임은 대표에게 귀속됩니다. AI의 제안은 참모의 보고서지 결재가 아닙니다.
3. **전문가의 책임 있는 자문** — 저는 세무사·변호사·노무사가 아닙니다. AI는 이해를 돕고 초안을 만들지만, 계약·감면 신청·분쟁은 자격 있는 전문가의 검토가 필요합니다.
4. **B2B 영업 클로징과 파트너십** — 신뢰는 사람 사이에서 생깁니다.
5. **AI 결과물의 검증** — AI는 틀린 내용을 그럴듯하게 말할 수 있습니다(환각). 특히 코드의 보안, 법·세무 수치는 반드시 교차 확인하는 습관이 창업자의 핵심 역량입니다.
