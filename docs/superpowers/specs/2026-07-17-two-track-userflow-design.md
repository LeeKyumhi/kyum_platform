# 투트랙 이원화 유저플로우 재설계 — 디자인 스펙

- 날짜: 2026-07-17
- 상태: 사용자 리뷰 대기
- 배경 문서: `app/PROGRESS.md` "법률 컴플라이언스 트랙"(2026-07-13), `창업 체크리스트/startup-platform-business-guide.md`

## 1. 배경과 목적

관광진흥법 제38조상 외국인 대상 유상 관광안내는 관광통역안내사 자격 보유자만 가능하다.
백엔드 게이팅(ServiceCategory·GuideVerification·예약 3중 게이팅)은 2026-07-13 세션에서 이미 구현됐지만,
**제품 UX는 여전히 "가이드 찾기" 단일 프레임**이라 다음 문제가 남아 있다:

1. 대다수 공급자는 무자격(동행 파트너)인데, 이들에게 서비스가 "기능이 잠긴 가이드"로 보인다.
2. 이용자(여행자)가 무자격 파트너에게 관광안내를 기대할 오해 여지가 있다.
3. 자격 보유자의 투어 서비스와 동행 서비스가 UI에서 구분되지 않는다.

이 스펙은 **프론트 중심의 투트랙 재설계**를 정의한다. 백엔드 변경은 additive 최소(§8).

## 2. 확정 결정 (사용자 승인)

| 결정 | 내용 |
|---|---|
| IA | **투트랙 완전 분리** — "🎫 인증 가이드 투어" / "🤝 로컬 동행" 두 세계 |
| 호칭 | 무자격 공급자 = **"동행 파트너"** (en: Companion, zh: 同行伙伴). 인증자 = "인증 가이드". 동행 컨텍스트에서 '가이드' 단어 금지 |
| 온보딩 | **초입 자격 분기** — "자격증이 있나요?" 없음→동행만 / 있음→투어+동행 둘 다 (인증 승인 전엔 동행만 활성) |
| 예약 모델 | 동행 = **시간제 유지 + 카테고리별 요청 폼**. 투어 = 현행 무변경 |
| 여행일정 | 모바일 하단 탭 유지. 두 트랙 모두와 일정 통합 강화(§7) |

## 3. 용어·표기 규칙

- **동행 파트너** (Companion / 同行伙伴): 비관광 5개 카테고리 제공자. UI 어디서도 '가이드'로 부르지 않는다.
- **인증 가이드** (Certified Guide / 认证导游): `verificationStatus=VERIFIED` + `TOUR_GUIDE` 선언자.
- 카테고리 표기(이모지 고정): 🏥 병원·관공서 통역 / 🍽️ 식사 동행 / ☕ 카페 동행 / 🛍️ 쇼핑 통역 / 🗣️ 언어교환 / 🎫 투어(인증 전용).
- 제공자 통칭이 필요한 화면(온보딩·대시보드)에서는 **"파트너"** 를 쓴다(트랙 중립).

## 4. 라우팅 & 내비게이션

### 4-1. 라우트

| 라우트 | 변경 | 내용 |
|---|---|---|
| `/guides` | 개편 | **투어 트랙 전용 목록.** `GET /api/guides?category=TOUR_GUIDE` 고정 — 미인증자는 이 카테고리를 선언할 수 없으므로 서버 변경 없이 인증 가이드만 노출된다. Phase 2의 카테고리 칩 필터는 이 페이지에서 제거(언어 필터·정렬·투어코스 탭·게시글 피드 탭은 유지). 상단에 "관광통역안내사 인증 가이드" 트랙 설명 + 배지 설명 시트 |
| `/guides/[id]` | 소폭 | 투어 프레임 상세(현행 유지). 파트너가 동행 카테고리도 제공하면 "동행 서비스도 제공해요 → 동행 프로필 보기" 크로스링크 |
| `/companions` | 신규 | **동행 트랙.** ① 카테고리 타일 5개 → ② `CitySelect`+`DistrictSelect` → ③ 파트너 목록(`GET /api/guides?category=&city=` 재사용, `GuideCard` 변형: "동행 파트너" 배지·카테고리 태그·인증 배지는 인증자에게만). 카테고리 미선택 시 전체 동행 파트너 |
| `/companions/[id]` | 신규 | 동행 파트너 프로필 — `guides/[id]`와 컴포넌트 공유하되: 투어 코스 섹션 없음, 예약 위젯은 §6 카테고리 요청 폼, 법적 안내 박스(§9) 상시 노출, 인증 가이드면 투어 상세 크로스링크 |
| `/find` | 신규 | 모바일 "찾기" 탭용 경량 허브 — 두 트랙 진입 카드 + 동행 카테고리 숏컷(랜딩 진입 카드 컴포넌트 재사용). 데스크탑에서는 사이드바에 두 항목이 따로 있으므로 보조 페이지 |
| `/become-guide` | 개편 | §5 온보딩. 라우트 경로는 유지(기존 링크 호환), 페이지 카피는 "파트너 되기" |

### 4-2. 랜딩(`/`)

- 게스트 히어로 아래 **두 개의 대형 진입 카드**: 🎫 인증 가이드 투어(자격증 보유·관광 안내) / 🤝 로컬 동행(병원·쇼핑·식사·통역). 동행 카드 안에 카테고리 숏컷 5개.
- 여행자 홈(`/traveler`)에도 동일한 두 트랙 진입 섹션.
- 기존 Airbnb식 검색바는 투어 트랙(/guides)으로 연결 유지.

### 4-3. 사이드바 / 모바일 탭

- **데스크탑 레일(게스트)**: 홈 / 투어(`/guides`) / 동행(`/companions`) / 커뮤니티 / 탐색 / 여행일정
- **데스크탑 레일(여행자)**: 홈 / 여행자홈 / 투어 / 동행 / 메시지 / 커뮤니티 / 탐색 / 여행일정 / 내예약 / 팔로잉
- **모바일 하단 5탭(여행자)**: 🧳 홈 / 🔍 찾기(`/find`) / 💬 메시지 / 🗺️ 여행일정 / 👤 프로필
- **모바일 하단 5탭(게스트)**: 홈 / 찾기 / 커뮤니티 / 여행일정 / 로그인
- **제공자(구 가이드) 모드**: 메뉴 구성 유지하되 라벨 중립화 — "가이드홈"→"파트너홈" 등. `/guide/courses`(투어 코스) 항목은 **인증 가이드에게만 노출**(서버는 이미 게이팅, 메뉴만 숨김). localStorage `mode="guide"` 키·값은 기술 호환을 위해 유지하고 **UI 라벨만** 변경.

## 5. 제공자 온보딩 (become-guide 개편)

- **Step 0 (신규)**: "관광통역안내사 자격증이 있으신가요?" — 예/아니요 대형 카드 2개.
  - **아니요** → 동행 파트너 등록: 헤드라인·소개·도시·언어·시간당 요금·**동행 카테고리 선택(5개 중 1개 이상)**·호스트 약관 동의. 자격증/credential 업로드 단계 자체가 없다.
  - **예** → 동일 폼 + `TOUR_GUIDE` 카테고리 선택 가능 + **인증 신청 섹션 통합**(기존 `GuideVerification` 신청 플로우: 실명·자격증번호·자격증/신분증 업로드). 안내 문구: "인증 심사 중에도 동행 서비스는 바로 시작할 수 있어요" — 승인 전까지 투어 카테고리만 잠김(기존 서버 게이팅 그대로).
- Step 0 분기는 **UI 편의일 뿐 권한이 아니다** — 실제 투어 제공 권한은 오직 어드민 승인(VERIFIED)으로만 열린다. "예"를 골라도 승인 전엔 동행과 동일.
- 트랙별 CTA 진입: 투어 트랙에서 "가이드로 등록" → Step 0 "예" 프리셋, 동행 트랙에서 "파트너 되기" → "아니요" 프리셋(변경 가능).
- `guide/manage`: 기존 `ServiceCategoryPicker`·인증 신청 섹션 유지, 카피만 파트너 프레임으로 정리.
- 파트너홈(`/guide`): `serviceCategories` 미선언 기존 가이드에게 "제공 서비스를 선언해야 목록에 노출됩니다" 리마인더 배너(Phase 2 하드 컷오버 완화 장치).

## 6. 동행 예약 — 카테고리별 요청 폼

### 6-1. 프론트 폼

공통 필드(날짜·시작 시간·시간 수·메시지)에 카테고리별 필드 추가. 전부 선택 입력:

| 카테고리 | 추가 필드 |
|---|---|
| 🏥 MEDICAL_INTERPRETER | 기관명(병원·관공서), 방문 목적(진료과 등) |
| 🛍️ SHOPPING_INTERPRETER | 쇼핑 지역, 원하는 품목 |
| 🍽️ DINING_COMPANION | 원하는 음식·식당, "추천해 주세요" 체크 |
| ☕ CAFE_COMPANION | 메모 |
| 🗣️ LANGUAGE_EXCHANGE | 배우고 싶은 언어, 수준 |

- 예약 위젯 진입 컨텍스트(카테고리 타일→목록→상세)에서 카테고리 프리셋, 파트너가 선언한 카테고리 내에서만 선택 가능(기존 검증 유지).
- 슬롯 다중선택·수동 다중일 입력 등 기존 예약 메커니즘은 그대로 쓴다(카테고리 필드만 얹음).

### 6-2. 데이터

- `Booking.request_details` — **nullable text 컬럼 1개(additive)**. 카테고리별 필드를 JSON 문자열로 저장. 백엔드는 불투명 저장(placeCard 규약과 같은 철학) + 길이 상한(2,000자) 검증만.
- `CreateBookingRequest.requestDetails`(String, 선택) / `BookingResponse.requestDetails` 노출.
- 렌더: 예약 상세(`/bookings/[id]`)·가이드 예약 요청 카드(`/guide/requests`)에서 라벨:값 행으로 구조화 표시. 파싱 실패 시 plain text 폴백.
- 투어 예약: 무변경(requestDetails 미사용, null).

## 7. 여행일정 통합 (사용자 요청 반영)

- **이번 범위**:
  1. `ItineraryService.autoAddTourItem` 일반화 — 예약 확정 시 자동 추가되는 일정 아이템의 라벨·아이콘을 `Booking.serviceCategory` 기반으로(예: "🏥 병원 동행", "🎫 가이드 투어"). 현행은 동행 예약도 "🎫 가이드 투어"로 찍히는 버그성 동작. 아이템 category 값은 투어 예약이면 기존대로 `"tour"`(amber 스타일 유지), 동행 예약이면 `"companion"` 저장 — 일정 빌더에 companion 아이템 스타일(중립 톤) 추가.
  2. 일정 빌더(`/trips/[id]`) 일차 헤더에 **"이 날 함께할 파트너 찾기"** CTA — `/find`(또는 두 트랙)로 날짜 컨텍스트 쿼리와 함께 링크(링크만, 딥 프리필은 백로그).
- **백로그(IDEAS.md에 기록)**: 일정 기반 파트너 추천(도시·날짜 매칭) / 일정에서 바로 예약 요청(날짜·시간 프리필) / 예약+일정 통합 캘린더 뷰 / 공유한 일정을 보고 파트너가 견적·제안하는 플로우.

## 9. 신뢰·법적 메시징

- **동행 프로필·예약 폼 고정 안내 박스**: "동행 파트너는 관광안내(명소·문화유산 해설 등)를 제공할 수 없어요. 관광 안내가 필요하면 인증 가이드 투어를 이용하세요" + 투어 트랙 링크.
- **투어 트랙 배지 설명**: "관광통역안내사 인증" 배지 탭 시 짧은 설명 시트(자격·인증 절차).
- **'가이드' 단어 소탕**: 동행 컨텍스트(`/companions*`, `/find` 동행 카드, 동행 예약 폼, 파트너 온보딩 무자격 경로)의 ko/en/zh 카피에서 '가이드/Guide/导游' 제거 — 구현 후 grep으로 검증.
- 호스트 약관(기존 `hostTermsAgreedAt`)에 이미 "비관광 호스트의 관광안내 금지" 포함 — 문구 재확인만(변호사 검토는 별도 트랙).

## 10. i18n

- 신규 그룹: `tracks.*`(두 트랙 진입 카드·설명), `companions.*`(동행 목록·상세), `companionBooking.*`(카테고리별 폼 필드), `find.*`(허브), `onboardingFork.*`(Step 0). 기존 `serviceCategories.*` 재사용.
- 규칙 유지: **모든 키 ko/en/zh 3개 언어 필수**, 동적 데이터는 i18n에 넣지 않는다.

## 11. 마이그레이션·기존 영향

- 기존 가이드: Phase 2 하드 컷오버 유지(카테고리 선언 전 예약 불가) + §5 리마인더 배너로 완화.
- 기존 `/guides` 외부 링크: 투어 트랙으로 남으므로 무해. 컴포넌트(`GuideCard`·`ChatRoom`·예약 파이프라인·`SlotCalendar`) 전부 재사용.
- DB 삭제·리네임 없음. `mode` localStorage 값 변경 없음.
- 커뮤니티·DM·리뷰·팔로우는 두 트랙 공용(무변경).

## 12. 검증 계획

1. `cd app/frontend && npx tsc --noEmit` / `gradle compileJava`
2. Playwright: ① 온보딩 분기 2경로(무자격→동행만 등록, 유자격→인증 신청+동행 즉시 활성) ② 동행 탐색(카테고리→도시→목록→상세→카테고리 요청 폼 예약) ③ 투어 트랙 회귀(인증 가이드만 노출·기존 예약 플로우) ④ 예약 상세·요청 카드에 requestDetails 구조화 렌더 ⑤ 일정 자동 추가 라벨(동행 예약 → "🏥 병원 동행")
3. i18n 3언어 parity + 동행 컨텍스트 '가이드' 단어 grep 0건
4. 모바일 뷰: 하단 5탭(찾기·여행일정 포함) 렌더
